# 用电负荷预测与储能调度优化｜技术方案

版本：v0.1，2026-10-20

使用方法见 [README](../README.md)。

本文说明当前实现的模块、计算口径、配置和验证方法。

## 1. 范围与技术栈

程序在本地完成“数据整理 → 次日预测 → 调度求解 → 真实负荷回测 → 导出”。每个目标日单独运行 24 个时段，比较无储能、固定规则、预测驱动优化三种策略。电池每天使用相同初始电量，期末回到该值，不串接跨日状态。

运行环境为 Python 3.12，业务依赖为 pandas、NumPy、PuLP 和 Matplotlib；配置与命令行使用标准库 tomllib、argparse。`pyproject.toml`、`uv.lock` 和 `.python-version` 固定环境，pytest 用于验证。

已实测 Windows、Python 3.12.10、CBC 2.10.3。CBC 启动检查会求解已知最优值的小模型；导入 PuLP 成功不等于求解器可用。

## 3. 数据与时间口径

读取 UCI 分号文件中的 `Date`、`Time` 和 `Global_active_power`，按日/月/年解析时间，功率单位为 kW。`?`、空值、非有限数值和负功率均不可用于负荷计算。

1. 按所用字段删除完全相同的重复记录。同一时间戳有不同值时记为冲突，不任意保留其中一条。
2. 建立连续分钟网格。历史缺失最多前向填补 5 分钟，不反向填补、不跨冲突时刻填补。突变只标记，不按实验收益删改。
3. 每小时有 60 个有效分钟时计算平均功率 `load_kw`，电量为 `load_kw × 1 h`。记录原始观测、填补和缺失数量。
4. 真实回测日要求 24 小时均有完整原始观测。含填补、缺失或冲突的日期不进入正式费用评价。

按数据中的当地钟表时间处理，不推断时区。小时表保存 `timestamp`、`load_kw`、`load_kwh`、`observed_count`、`imputed_count` 等列。来源、下载时间和 SHA-256 写入元数据；原始文件不修改。

默认日期 2010-01-04 至 2010-01-10 仅按观测完整性选择，未根据收益筛选。前一个测试日的观测在下一日开始时已知，可用于下一日预测。

## 4. 预测与误差

对目标日 D 的小时 h，使用前一日同小时负荷：

$$
\widehat L_{D,h}=L_{D-1,h},\qquad h=0,\ldots,23.
$$

按日期和小时对齐，前一日 24 小时历史不足则记为 `forecast_unavailable`，不在删去缺失行后取“前 24 行”。预测误差为：

$$
\mathrm{MAE}=\frac{1}{N}\sum_{i=1}^{N}|\widehat L_i-L_i|,
\qquad
\mathrm{RMSE}=\sqrt{\frac{1}{N}\sum_{i=1}^{N}(\widehat L_i-L_i)^2}.
$$

两指标单位均为 kW，分别保存逐日与整体指标、日期和样本量。预测评价日期与费用共同有效日期是两个集合。

## 5. 储能调度模型

取 24 个时段，Δt = 1 h。功率在电网与负荷侧计量，电量在电池内部计量，效率只进入电量递推一次。

| 符号 | 含义 | 单位 |
| --- | --- | --- |
| L̂_t、π_t | 预测负荷、购电价格 | kW、元/kWh |
| c_t、d_t、g_t | 充电、放电、购电功率 | kW |
| E_t | 时段开始时的电池电量，t = 0,…,24 | kWh |
| z_t | 充放电模式，1 允许充电，0 允许放电 | 二进制 |
| η_c、η_d | 充电与放电效率 | 无量纲 |

目标为最小化预测购电费用：

$$
\min\sum_{t=0}^{23}\pi_t g_t\Delta t.
$$

约束为：

$$
\begin{aligned}
g_t &= \widehat L_t+c_t-d_t, & g_t&\ge 0,\\
0&\le c_t\le P_c^{\max}z_t, &
0&\le d_t\le P_d^{\max}(1-z_t),\\
d_t&\le\widehat L_t, & z_t&\in\{0,1\},\\
E_{t+1}&=E_t+\eta_c c_t\Delta t-\frac{d_t\Delta t}{\eta_d},\\
E_{\min}&\le E_t\le E_{\max}\quad(t=0,\ldots,24),\\
E_0&=E_{\mathrm{initial}}, & E_{24}&=E_{\mathrm{initial}}.
\end{aligned}
$$

互斥上界直接使用设备最大功率。配置要求电价非负、效率位于 (0,1]，且 `0 ≤ E_min ≤ E_initial ≤ E_max ≤ capacity_kwh`。

CBC 默认单线程，单日时限 30 秒。联合检查 PuLP 问题状态、解状态和 CBC 日志，只有证明最优的解才接受；不可行、无界、超时、未证明最优及调用错误分别记录。随后独立重算电量轨迹、互斥、功率、电量边界、初末电量与费用，默认绝对容差 `1e-6`。

## 6. 对照、回测与比较

无储能的实际购电功率等于真实负荷。固定规则在预先设定的低价窗口 C 充电、高价窗口 H 放电，全部充电时段早于放电时段。为满足期末回到期初，先确定一次循环的电池内部电量：

$$
A=\min\left\{
E_{\max}-E_{\mathrm{initial}},\quad
\eta_c P_c^{\max}\Delta t\,|C|,\quad
\frac{\Delta t}{\eta_d}\sum_{t\in H}\min(P_d^{\max},\widehat L_t)
\right\}.
$$

按时间顺序充入 A，再按功率、预测负荷和剩余电量上限取出 A，窗口外空闲。该规则不调用优化器，也不使用目标日真实负荷倒推动作。

计划确定后，用真实负荷逐小时检验：

$$
d_t\le L_t^{\mathrm{actual}},\qquad
g_t^{\mathrm{actual}}=L_t^{\mathrm{actual}}+c_t-d_t\ge 0.
$$

同时复核电池约束。放电超过真实负荷时记为 `replay_infeasible`，保存首个失败时段、违反量和逐时详情，不截断放电或修补后续电量。只有全日通过才计算实际费用；失败方案的费用、差额和节省率留空。

费用差额为“无储能费用 − 策略费用”，正值表示节省。总费用与整体节省率只在三策略共同有效日期计算，基准为零时节省率留空。另列数据排除、预测不可用、求解失败、回测不可执行和覆盖率。这种事后有效条件比较不代表完整测试期收益。

## 7. 配置与运行

以下示例与 `configs/example.toml` 一致。起止日期均包含在测试期内，电价和电池均为假设情景。

```toml
[experiment]
name = "baseline_storage_v01"
test_start = "2010-01-04"
test_end = "2010-01-10"
output_dir = "outputs"

[data]
path = "data/raw/household_power_consumption.txt"
source_url = "https://archive.ics.uci.edu/dataset/235/individual+household+electric+power+consumption"
history_ffill_limit_minutes = 5
evaluation_require_observed = true

[tariff]
currency = "CNY"
source = "实验情景，非该家庭真实电价"
hourly_prices = [
  0.30, 0.30, 0.30, 0.30, 0.30, 0.30, 0.30,
  0.60, 0.60, 0.60, 0.60, 0.60, 0.60, 0.60, 0.60, 0.60, 0.60,
  1.00, 1.00, 1.00, 1.00, 1.00,
  0.60, 0.60
]

[battery]
source = "实验情景，非该家庭真实设备"
capacity_kwh = 5.0
min_energy_kwh = 0.5
max_energy_kwh = 4.5
initial_energy_kwh = 2.5
max_charge_kw = 2.0
max_discharge_kw = 2.0
charge_efficiency = 0.95
discharge_efficiency = 0.95

[fixed_rule]
charge_hours = [0, 1, 2, 3, 4, 5, 6]
discharge_hours = [17, 18, 19, 20, 21]

[solver]
time_limit_seconds = 30
threads = 1
# cbc_path = "C:/path/to/cbc.exe"

[validation]
absolute_tolerance = 0.000001
```

相对路径以项目根目录为基准，从该目录执行：

```powershell
uv sync --locked
uv run load-storage doctor
uv run load-storage download-data
uv run load-storage run --config configs/example.toml
uv run pytest
```

下载命令不覆盖已有文件，实验运行不联网。`doctor` 检查 Python、CBC 实际求解和中文绘图。全部请求日期成功时返回 0；单日失败会保存诊断和其余结果，最终返回非零状态。默认实跑因五日回测不可执行而返回 1。

## 8. 输出与验证

每次实验写入新的 `outputs/<run_id>/`，保留配置、来源和版本记录。

| 输出 | 内容 |
| --- | --- |
| `config.toml`、`metadata.json` | 配置、数据来源与哈希、代码和环境版本 |
| `data_quality.json`、`hourly.csv` | 清洗与逐日质量记录、小时负荷 |
| `predictions.csv`、`schedule.csv` | 预测、真实值、计划与电量轨迹 |
| `cost_comparison.csv`、`summary.json` | 每日费用与状态、误差和共同日期汇总 |
| `diagnostics.json` | 逐时约束违反情况 |
| `figures/`、`run.log`、`solver_logs/` | PNG/SVG、运行和 CBC 日志 |

CSV 使用带 BOM 的 UTF-8，JSON 保留中文。无效日调度图标注不可执行，不进入有效费用图的汇总。

90 项 pytest 测试覆盖单位、缺失与冲突、时间对齐、防信息泄漏、已知最优解、设备约束、求解失败、实际回测和结果复现。文档检查校验编码、章节、链接、表格及 TOML 与配置的一致性。

默认七日 168 小时的 MAE 为 0.701245 kW，RMSE 为 0.991260 kW。只有 2010-01-05 与 2010-01-10 三策略共同有效，覆盖率 2/7；这两日优化费用为 50.050614 元，相对无储能费用 53.861140 元减少 7.0747%。其余五日是回测不可执行，不能称作求解失败。

费用不含投资与老化。当前不处理滚动控制、预测不确定性、光伏和售电；电池参数情景对照也不等同于单因素容量分析。
